# MYGOLD · 基金实时估值

用基金公示的季报重仓，配上持仓股当前涨跌幅，估算出还没公布的当日净值涨跌，并换算成具体的盈亏金额。

对应仓库：[hemeng88/MYGOLD](https://github.com/hemeng88/MYGOLD)
部署与运维见 [部署说明.md](./部署说明.md)。

> 名字和域名（ohmygold.icu）是历史遗留。项目原本采集浙商积存金曲线，黄金相关功能已全部移除。

## 它做什么

- **收藏基金**，按代码或名称搜索添加
- **实时估值**：`Σ(某股占净值比例 × 该股当日涨跌幅)`，盘中每分钟更新
- **盈亏金额**：填入持有份额和成本价，给出今日估算盈亏、累计盈亏和收益率，多只基金还有合计
- **涨幅榜穿透**：把榜首基金的重仓汇总，看清当期领涨的是哪个方向

## 估值是怎么算的

季报只公示前十大重仓（指数基金会多几只），永远只能覆盖一部分净值，所以同时给两个数：

| | 算法 | 含义 |
| --- | --- | --- |
| 保守估算 | `Σ(权重 × 涨跌幅)` | 没公示的仓位当作不动，是净值涨跌的下限 |
| 估算涨跌 | 上式再除以覆盖度 | 假设没公示的仓位与重仓同步，即市面上「基金估值」的常规口径 |

界面同时给出**覆盖度**，覆盖 90%+ 的指数基金两个数几乎重合，偏股混合基金差距明显。

实测校验：招商中证白酒（161725）估算 **-1.289%**，其跟踪的中证白酒指数实际 **-1.379%**，差 0.09 个百分点，覆盖度 94.77%。

两种情况会主动拒绝出数，而不是给个看着像样的错数：

- **覆盖度低于 20%**：债券基金可能只公示 0.3% 的股票仓位，按覆盖度放大会得出荒谬结果
- **只填份额不填成本价**：否则成本按 0 算，会显示成「整笔都是赚的」

**货币基金**单独处理：净值接口返回的 `NAV` 其实是万份收益，货币基金单位净值恒为 1.0000、收益以份额结转，直接乘份额会算出上千元假亏损。

## 涨幅榜为什么要穿透

基金名字说明不了方向 —— 「易方达供给改革」和「产业机遇」实际都是半导体设备。所以拉榜单前 10 名，把每只的季报重仓汇总，被反复重仓的股票才是真主线。

某次实测结果：

```
今年来 → 半导体设备    中科飞测 7/10 只重仓、北方华创 5/10、华峰测控 5/10
近3月  → CXO/创新药    药明康德 10/10 只重仓（合计权重 96.5%）、凯莱英 10/10
```

再反过来按基金聚合一次，看**谁的仓位最集中在这条主线上**。得分按共识度加权，全榜参与、不做截断：

```
共识度 = 该股被多少只榜单基金共同重仓 / 榜单基金总数
得分   = Σ(持仓权重 × 共识度)
抱团度 = 得分 / 披露仓位

近1年（半导体）          得分  抱团度
  #1 东方人工智能主题A    39.1   41%
  #2 银华集成电路A        37.7   40%
近3月（CXO）
  #1 招商前沿医疗保健A    53.7   61%
  #2 招商品质成长A        52.4   58%
```

近3月抱团度明显高于近1年，说明医药这条主线比半导体抱得更紧。

不能用「压在前 N 大重仓股上的权重合计」：集合放大后会覆盖榜单基金几乎所有持仓，得分恒等于披露仓位，榜就退化成「谁满仓程度最高」。比较范围是上榜基金的并集，不是全市场。A/C 份额按持仓指纹合并，否则「前五」里一半是同门份额。

支持近1月 / 近3月 / 近6月 / 近1年 / 今年来。榜单是后视镜，照着它买就是追高。

## 数据来源

持仓来自天天基金季报明细（JSONP 包 HTML，按标签解析），名称与净值来自天天基金移动端接口，行情走东方财富，A 股和港股同一个接口。

持仓股行情做了 **push2 → push2delay 镜像 → 新浪** 三级兜底：push2 请求密了会直接断连，实测丢一批能让覆盖率从 94% 掉到 66%，估算随之失真。新浪只认 A 股和港股，美股取不到时由覆盖度如实反映。

季报持仓一个季度才变一次（每天 16:40 对一遍），持仓股报价才是盘中要一直刷的（每 60 秒，仅交易时段）。

## 本地启动

需要 Python 3.9+ 和 Node 18+。

```bash
chmod +x start.sh
./start.sh
```

- 前端：<http://127.0.0.1:5173>
- 健康检查：<http://127.0.0.1:8000/api/health>
- 数据库：`backend/data/mygold.db`

技术栈：FastAPI + SQLAlchemy + APScheduler + SQLite；React 18 + Mantine 7 + Vite。外部请求只用 httpx。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/funds` | 收藏列表 + 实时估值 + 盈亏 |
| GET | `/api/funds/{code}` | 单只详情，含逐只持仓贡献 |
| GET | `/api/funds/search?q=` | 搜基金 |
| POST | `/api/funds/favorites` | 新增收藏 |
| PUT | `/api/funds/favorites/{code}/position` | 存份额和成本价 |
| GET | `/api/funds/rankings?period=` | 涨幅榜 + 穿透出的领涨方向 |

完整清单见 [部署说明.md](./部署说明.md) 第 6 节。

## 登录

账号存在数据库 `users` 表，密码只存 PBKDF2-HMAC-SHA256 加盐哈希（26 万轮，标准库实现，没引入 bcrypt/passlib）。`POST /api/auth/login` 换取 HMAC 签名的令牌，之后请求带 `Authorization: Bearer <令牌>`。除 `/api/health` 外所有 `/api/funds*` 都需要登录。

**没有注册和改密界面**（单人自用），**代码里也没有默认密码** —— 写进仓库的密码等于公开密码。空库首次启动时按 `.env` 里的 `MYGOLD_BOOTSTRAP_PASSWORD` 建号，没配就不建号、登录一直失败并在日志里提示。改密码走 `backend/scripts/set_password.py`。

**收藏和持仓按账号隔离**，每个账号只看得到自己的数据。基金持仓明细、净值、涨幅榜是市场数据，多账号共享。

已知短板：站点目前是明文 HTTP，密码和令牌明文传输；没有登录失败次数限制。详见 [部署说明.md](./部署说明.md) 第 6 节。

## 这不是投资建议

这里算的是**估算值**，不是官方净值。季报持仓有滞后（超过 150 天会标记为过期报告），未公示的仓位只能靠假设，估算和实际净值必然有偏差。所有数字仅供参考。
