# MYGOLD · 基金实时估值

用基金公示的季报重仓，配上持仓股当前涨跌幅，估算出还没公布的当日净值涨跌，并换算成具体的盈亏金额。

对应仓库：[hemeng88/MYGOLD](https://github.com/hemeng88/MYGOLD)
部署与运维见 [部署说明.md](./部署说明.md)。

> 名字和域名（ohmygold.icu）是历史遗留。项目原本采集浙商积存金曲线；黄金页面、持仓和分析已移除，现在只在每日持仓收盘播报里查询一次实时金价。

## 它做什么

- **收藏基金**，按代码或名称搜索添加
- **实时估值**：`Σ(某股占净值比例 × 该股当日涨跌幅)`，盘中每分钟更新
- **盈亏金额**：填入持有份额和成本价，给出今日估算盈亏、累计盈亏和收益率，多只基金还有合计
- **穿透到个股**：份额 × 净值 × 公示仓位，算出你实际持有多少钱的某只股票，同一只股票跨基金合并
- **涨幅榜穿透**：把榜首基金的重仓汇总，看清当期领涨的是哪个方向
- **可买主板**：新开户通常只能买沪深主板，页面列出沪深300里的主板样本，现价对照近1月 / 3月 / 6月 / 今年来 / 近1年均价，可按当日涨跌、区间涨跌、偏离均价排序；点开个股看走势和同期大盘对比
- **杂项倒计时**：单次日期（游戏发售）或每月循环（发工资），可选到分钟；按账号隔离。列表里自动带下一次法定假期（国务院办公厅放假通知，目前覆盖 2026–2027 年）

## 估值是怎么算的

季报只公示前十大重仓（指数基金会多几只），永远只能覆盖一部分净值，所以同时给两个数：

| | 算法 | 含义 |
| --- | --- | --- |
| 保守估算 | `Σ(权重 × 涨跌幅)` | 没公示的仓位当作不动，是净值涨跌的下限 |
| 估算涨跌 | 上式再除以覆盖度 | 假设没公示的仓位与重仓同步，即市面上「基金估值」的常规口径 |

界面同时给出**覆盖度**，覆盖 90%+ 的指数基金两个数几乎重合，偏股混合基金差距明显。

实测校验：招商中证白酒（161725）估算 **-1.289%**，其跟踪的中证白酒指数实际 **-1.379%**，差 0.09 个百分点，覆盖度 94.77%。

三种情况会主动拒绝出数，而不是给个看着像样的错数：

- **覆盖度低于 20%**：债券基金可能只公示 0.3% 的股票仓位，按覆盖度放大会得出荒谬结果
- **只填份额不填成本价**：否则成本按 0 算，会显示成「整笔都是赚的」
- **最新净值已经把这场行情算进去**：见下节

### 净值一公布，估算就得停

`估算净值 = 已公布净值 × (1 + 估算涨跌)` 只在净值还不含这段涨跌时成立。收盘后、周末、节假日行情接口**不会把涨跌幅清零**，而基金当晚 20-21 点公布当日净值 —— 两者一相乘就是把同一场行情算两遍。曾经的实际故障：周末和每天开盘前打开，今日估算盈亏和累计盈亏都多算一份（实测一只 5000 份的基金虚高 101 元）。

修法是给每条报价记下它属于哪个交易日（`fund_stock_quotes.trade_date`）。`nav_date >= trade_date` 时判定为已结算，不再重复使用重仓股行情估算，改用基金官方日涨跌和官方净值；下一个交易日开盘后再自动回到穿透估算。

交易日只能用**上证指数日 K**来定：行情快照里的时间字段（东财 `f86`/`f124`、腾讯第 30 段）实测都是服务器当前时间，收盘后照样往前跑；日 K 在非交易日不会多出一根，节假日也骗不过去。

**货币基金**单独处理：净值接口返回的 `NAV` 其实是万份收益，货币基金单位净值恒为 1.0000、收益以份额结转，直接乘份额会算出上千元假亏损。

## 涨幅榜为什么要穿透

基金名字说明不了方向 —— 「易方达供给改革」和「产业机遇」实际都是半导体设备。所以拉榜单前 10 名，把每只的季报重仓汇总，被反复重仓的股票才是真主线。

某次实测结果：

```
今年来 → 半导体设备    中科飞测 7/10 只重仓、北方华创 5/10、华峰测控 5/10
近3月  → CXO/创新药    药明康德 10/10 只重仓（合计权重 96.5%）、凯莱英 10/10
```

再反过来找**全市场谁把最多净值压在这条主线上**。主线由涨幅榜识别，候选基金按股票反查全市场，不局限于上榜基金：

```
主线代表股 = 该周期榜单基金重仓股里最抱团的前 15 只
主线仓位   = 该基金净值里压在这些股票上的比例之和

今年来                        主线仓位  命中
  #1 财通品质甄选混合A          73.7%   10/15
  #2 财通成长优选混合A          72.3%   10/15
近3月
  #1 中欧医疗健康混合A          64.8%   13/15
  #2 大摩优悦安和混合A          59.7%   12/15
```

早先两版只在上榜基金里比，是循环论证 —— 用因为押中主线而胜出的基金去衡量谁押中主线。反查之后 `中欧医疗健康混合A`、`银华智享混合A` 这些原本不在榜上的基金才浮出来，而且「主线仓位」是能验算的占净值比例。

支持近1月 / 近3月 / 近6月 / 近1年 / 今年来。榜单是后视镜，照着它买就是追高。

## 数据来源

持仓来自天天基金季报明细（JSONP 包 HTML，按标签解析），名称与净值来自天天基金移动端接口，行情走东方财富，A 股和港股同一个接口。

持仓股行情做了 **push2 → push2delay 镜像 → 新浪** 三级兜底：push2 请求密了会直接断连，实测丢一批能让覆盖率从 94% 掉到 66%，估算随之失真。新浪只认 A 股和港股，美股取不到时由覆盖度如实反映。

交易日同样不靠单家：上证指数日 K 按 **腾讯 → 新浪 → 东财** 三家取最大值。`push2his` 和 `push2` 一样会断连（实测连续 6 次全失败），而拿不到交易日就只能保守停掉估算，不能让核心功能取决于单个接口。

季报持仓一个季度才变一次（每天 16:40 对一遍），持仓股报价才是盘中要一直刷的（每 60 秒，仅交易时段）。交易日 16:10 会为收盘播报额外刷新一次数据库中所有实际持仓的行情，并查询一次浙商积存金实时价：京东金业接口为主源，GoldMonitor 为兜底。

## 登录

账号存在数据库 `users` 表，密码只存 PBKDF2-HMAC-SHA256 加盐哈希（26 万轮，标准库实现，没引入 bcrypt/passlib）。`POST /api/auth/login` 换取 HMAC 签名的令牌，之后请求带 `Authorization: Bearer <令牌>`。除 `/api/health` 外所有 `/api` 都需要登录。

**没有注册和改密界面**（单人自用），**代码里也没有默认密码** —— 写进仓库的密码等于公开密码。空库首次启动时按 `.env` 里的 `MYGOLD_BOOTSTRAP_PASSWORD` 建号，没配就不建号、登录一直失败并在日志里提示。改密码走 `backend/scripts/set_password.py`。

**收藏、持仓和倒计时按账号隔离**，每个账号只看得到自己的数据。基金持仓明细、净值、涨幅榜是市场数据，多账号共享。

已知短板：站点目前是明文 HTTP，密码和令牌明文传输；没有登录失败次数限制。详见 [部署说明.md](./部署说明.md) 第 6 节。

## OpenClaw / 飞书收盘播报

项目只向 OpenClaw 发送一种消息：**每个交易日 16:10 的持仓收盘播报**。此前的盘中 1% 阈值提醒、工作日早晨近月榜首提醒和采集失败告警均已停用，不再发飞书。

播报在 A 股和港股都收盘后执行。发送前会刷新一次持仓行情，再从数据库 `fund_favorites` 读取指定账号**所有填写了份额和成本价的基金与股票**，不写死基金代码：

```text
每日持仓收盘播报
交易日：2026-11-12
整体当日收益率：+0.82%
整体累计收益率：-2.35%
实时金价：854.27 元/克（浙商积存金）
```

口径：

- 整体当日收益率 = `Σ当日盈亏 ÷ Σ前一交易日市值`。
- 整体累计收益率 = `Σ(当前市值 - 份额 × 成本价) ÷ Σ(份额 × 成本价)`。
- 基金复用页面的穿透估值，直接持有的股票用收盘价；已公布官方净值时复用官方日涨跌。只有报价或官方净值日期等于播报交易日才计入当日收益，避免刷新失败时把昨天的涨跌冒充今天。某项缺行情或净值时不把它只塞进分母，并在消息末尾附上 `数据覆盖：当日 x/y 只，累计 x/y 只`。
- 实时金价是浙商积存金人民币/克，京东金业为主源、GoldMonitor 兜底；两家都失败时仍发送持仓收益，金价显示“获取失败”。
- 是否为交易日由上证指数日 K 判断，周末和法定休市日不发。

服务器 `.env`：

```dotenv
MYGOLD_OPENCLAW_WEBHOOK_URL=http://host.docker.internal:18789/hooks/agent
MYGOLD_OPENCLAW_WEBHOOK_TOKEN=OpenClaw生成的token
MYGOLD_OPENCLAW_TARGET=飞书接收人的open_id
MYGOLD_OPENCLAW_REPORT_USERNAME=hemeng
MYGOLD_PORTFOLIO_REPORT_HOUR=16
MYGOLD_PORTFOLIO_REPORT_MINUTE=10
MYGOLD_OPENCLAW_TIMEOUT_SECONDS=15
```

`MYGOLD_OPENCLAW_REPORT_USERNAME` 留空时沿用 `MYGOLD_BOOTSTRAP_USERNAME`。项目向 `/hooks/agent` 发带 `Authorization: Bearer <token>` 的 `POST` JSON，并通过 `deliver=true`、`channel=feishu`、`to=<open_id>` 显式投递。收益率由后端确定性计算，发给 OpenClaw 的提示要求原样转发，不让 agent 改写数字。

OpenClaw 和本项目在同一台服务器、但本项目运行在 Docker 中时，URL 使用 `http://host.docker.internal:18789/hooks/agent`；`docker-compose.yml` 已通过 `host.docker.internal:host-gateway` 打通容器到宿主机。

## 这不是投资建议

这里算的是**估算值**，不是官方净值。季报持仓有滞后（超过 150 天会标记为过期报告），未公示的仓位只能靠假设，估算和实际净值必然有偏差。所有数字仅供参考。
